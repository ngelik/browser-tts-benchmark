# Five additional small English TTS models

Selection snapshot: **2026-11-10**, frozen before performance testing.

Curated five new English small-model families, balancing HF monthly downloads and likes; not a global objective top-five ranking. Search top 100 text-to-speech repos sorted by downloads and likes plus supplemental named-family checks. Tiny/small bound: no more than 100M required neural synthesis parameters including decoder; public weights, English, one case per family, exclude existing benchmark models. Download counts are repository-level activity, not unique users or quality scores.

| Selected source | Monthly downloads | Likes | Selection reason |
|---|---:|---:|---|
| [hexgrad/Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) | 12,522,206 | 7,392 | Very high download adoption and likes; established official JavaScript runtime. |
| [KittenML/kitten-tts-nano-0.8-fp32](https://huggingface.co/KittenML/kitten-tts-nano-0.8-fp32) | 304,480 | 40 | High-download 15M English checkpoint; FP32 for common CPU/GPU configuration. |
| [ampixa/sanoTTS](https://huggingface.co/ampixa/sanoTTS) | 558,240 | 77 | High-download sub-3M family and official browser WASM runtime; Amy selected as English checkpoint. |
| [owensong/Inflect-Micro-v2](https://huggingface.co/owensong/Inflect-Micro-v2) | 414 | 454 | 454 likes for a complete 9.36M English stack with official ONNX export. |
| [facebook/mms-tts-eng](https://huggingface.co/facebook/mms-tts-eng) | 47,474 | 184 | Established 36M English model with substantial downloads and official Transformers.js support. |

The benchmark cases are Kokoro 82M FP32 (`af_heart`), Kitten Nano 0.8 FP32
(Bella), Sano Amy 1.46M FP32, Inflect Micro v2 FP32, and MMS English FP32.
Downloads/likes describe the named source repository; the asset lock separately
pins official or maintainer-provided browser/ONNX exports. A family repository
count is not claimed to be the selected voice checkpoint's download count.

## Why other candidates were deferred

- **kyutai/pocket-tts October tiny 1.9M/6.9M**: Exact tiny weights gated; no verified browser runtime for these new architectures. Older 100M community ports do not establish tiny-checkpoint support.
- **pnnbao-ump/VieNeu-TTS-v3-Turbo**: 130,907,520 backbone parameters before codec exceed the selected complete-stack 100M bound.
- **pnnbao-ump/VieNeu-TTS-v3-Nano**: Vietnamese-only checkpoint; English required.
- **OpenMOSS-Team/MOSS-TTS-Nano-100M**: 100M language model plus required ~22M audio tokenizer exceeds complete-stack bound.
- **myshell-ai/MeloTTS-English**: Requires BERT-base-uncased frontend in addition to synthesis model; complete neural stack exceeds bound.
- **ekwek/Soprano-1.1-80M**: 80M backbone plus separate 121MB decoder; lower monthly downloads than selected established families. Deferred, not judged inferior.
- **canberkkkkkk/ema-lightning**: Turkish-only; English required.
- **Existing eight benchmark cases**: User requested additional models; no duplicate cases.

The published campaign contains **20 completed attempts: 18 measured and two
unsupported Sano WebGPU attempts**. Ten attempts cover warm CPU/GPU generation
(one excluded full article plus five scored articles per supported path); ten
cover separate cached generation-RAM diagnostics (one article per supported path).
All use native arm64 on the same MacBook Pro, Apple M1 Pro, 8 CPU cores, 16 GiB
RAM, Darwin 25.6.0 (macOS) and **Google Chrome 157.0.8103.40**, with source
`955a87683c0c899cc299161a7b8b127fb75617be`. Earlier reference measurements used
other Chrome/source cohorts; their measurements are retained separately.

Cold-load checks were removed from this campaign's publication scope at the
user's request. The running cold check was cancelled, remaining cold work was
stopped, and all cold diagnostics from this campaign remain private. This scope
change is not a model failure. The original [25-cell plan](2026-11-10-campaign.json)
is retained as execution history; use the [20-cell warm/RAM plan](2026-11-10-warm-ram.json)
to reproduce the published scope. No cold results or 1 Mbps estimates enter this
campaign's published table or chart.

Sano has the shortest CPU median among these five configurations; Inflect has
the shortest WebGPU median. These are FP32 browser configurations, not claims
about every available precision/runtime or speech quality. Output duration differs
by model, so the overview also reports real-time factor. Listening quality has
not been rated; the nine recordings come from the fifth scored warm trial of
each supported model/backend.

Kokoro WebGPU averaged **394.93 MB** of sampled Chrome process-tree RSS, while its
largest generation-window sample reached **2,451.88 MB**. An average is not a
hardware memory-capacity requirement. The overview retains both means and sampled
maxima for every measured RAM cell. These values include Chrome baseline/workers,
may double-count shared pages, and do not measure total CPU-plus-GPU allocations
or VRAM. Sampled maxima can miss peaks between samples. RAM diagnostics are n=1
and their timings do not replace the warm measurements.

## Reproduce this campaign

Install dependencies, fetch each selected model's assets, verify baseline
eligibility with the skill, and use a clean published checkout:

```sh
caffeinate -di node tools/run-campaign.mjs --plan docs/discovery/2026-11-10-warm-ram.json --machine "Actual hardware / RAM" --accept-license
```

On macOS, `caffeinate -di` holds temporary idle/display-sleep assertions only while
the campaign command runs. On other systems omit that macOS wrapper and record
the actual sleep policy. It does not change persistent power settings.
Replace the machine label with the actual hardware; it is not a hardware override.
The plan preserves the preselected seed and order of the 20 retained attempts.

To reproduce the exact original implementation, first save the scope plan outside
the checkout, then check out the recorded source before installing dependencies
and fetching assets. For example, from a clean clone on the published result branch:

```sh
plan_file=$(mktemp)
git show HEAD:docs/discovery/2026-11-10-warm-ram.json > "$plan_file"
git switch --detach 955a87683c0c899cc299161a7b8b127fb75617be
npm ci
# After reviewing the applicable model/runtime terms:
for model in kokoro-82m kitten-nano-0.8 sano-amy inflect-micro-v2 mms-english; do
  npm run assets -- fetch --model "$model" --accept-license || exit 1
done
caffeinate -di node tools/run-campaign.mjs --plan "$plan_file" --machine "Actual hardware / RAM" --accept-license
```

Record actual power/background conditions in your plan. Runs are sequential and
use disposable Chrome profiles. Every retained attempt stays in the evidence.
The runner stops on unexpected errors or insufficient generation-RAM evidence
for inspection; it does not upload, retry failures, or silently skip cells.
Status is saved under ignored `runs/`. CPU FP32 repetitions can take many hours.
Publication follows the ordinary result PR workflow and baseline policy; smoke
diagnostics are never submitted as scores.
